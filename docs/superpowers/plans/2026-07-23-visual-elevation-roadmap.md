# STEM Hub Host 下一阶段视觉优化技术路线

日期：2026-07-23  
状态：讨论稿  
前提：当前 1600×900 固定窗口、F11 全屏、日夜主题与硬件控制语义保持不变。

## 目标

下一阶段不再大改第一页结构，而是在现有 2×3 信息架构上提高一致性、状态可读性和长期可维护性。所有视觉调整都应由真实设备状态驱动，避免为了“看起来丰富”添加虚假指标。

## 第一阶段：统一设计令牌和组件状态

1. 把卡片圆角、描边透明度、控件高度、间距、阴影、辉光和动画时长集中到 `theme.py`。
2. 为按钮、开关、状态徽章建立统一状态矩阵：
   - 默认
   - 悬停
   - 按下
   - 聚焦
   - 禁用
   - 等待设备确认
   - 命令失败
3. 将仍散落在 QSS 和自绘控件中的颜色常量替换为语义令牌。

验收标准：

- 日夜主题不出现单独硬编码修补。
- 相同交互状态在不同控件上的亮度和动效节奏一致。
- 切换主题后无需重建窗口，所有自绘控件即时刷新。

## 第二阶段：强化信息层级和密度

1. 重新校准三列标题、数值、单位、辅助标签的字号比例。
2. 电池、电机、温度、输出四类数据采用一致的“主值—单位—标签”基线规则。
3. 终端区降低装饰亮度，使实时控制区始终保持第一视觉优先级。
4. 对全屏模式单独校准留白和控件最大尺寸，避免只是简单等比放大。

验收标准：

- 5 秒扫视测试中，用户能依次识别电压、电机模式、电流、输出状态和最高温度。
- 1600×900 与常见 16:9 全屏分辨率下，核心基线偏差不超过 2 px。

## 第三阶段：建立统一运动语言

1. 保留电量环和温度槽的数值缓动，但统一持续时间和 easing。
2. 对等待设备确认的输出操作增加短暂的“pending”视觉状态；成功后落到稳定状态，失败时回滚并短促提示。
3. 电机模式切换采用轻量边框/辉光过渡，避免尺寸跳动。
4. 遵守低动态偏好：提供全局关闭非必要动画的设置入口。

建议节奏：

- 直接交互反馈：120–160 ms
- 状态切换：200–260 ms
- 遥测数值变化：300–450 ms
- 错误提示：不使用循环闪烁

## 第四阶段：增强设备状态语义

1. 将连接过程细分为离线、打开串口、握手、在线、错误，并只在状态徽章中呈现状态点。
2. 输出开关在命令确认前不可重复触发，降低硬件状态竞争。
3. 温度槽根据现有阈值切换冷色、正常色、警告色和危险色；阈值来自配置而非绘制代码。
4. 故障区支持“当前故障”和“已恢复但未确认”两种真实语义，前提是固件/API 能提供对应信息。

验收标准：

- UI 显示状态与最后一次设备确认状态一致。
- 超时、断线、设备拒绝三类失败均能回滚且不留下假开启状态。

## 第五阶段：视觉回归自动化

1. 为控制台、图表和透传页建立日夜主题黄金截图。
2. 覆盖固定窗口、全屏、连接、断开、禁用、告警和高温状态。
3. CI 中执行像素差异检查，同时设置结构性豁免区：
   - 字体抗锯齿边缘
   - 动画中的动态区域
   - 操作系统相关阴影
4. 保留关键几何断言，例如六键等距、卡片比例、温度槽归一化和开关位置。

建议门槛：

- 非动态区域平均 RGB 差异不高于 3/255。
- 关键控件位置误差不高于 2 px。
- 每轮视觉修改必须同时通过行为测试和黄金截图审查。

## 下一轮优先讨论项

1. 电机 MODE 区的大面积辉光是否继续保留，还是进一步收敛为工业仪表风格。
2. 温度卡是否加入“本组最高温度”的真实摘要，而不是继续四块完全等权。
3. 故障区是否需要最近一次故障时间；这需要先确认固件/API 能否提供可靠时间或事件序号。
4. 全屏模式是否维持当前三列比例，还是让中央电机区获得更高优先级。

推荐先做第一阶段和第五阶段。前者减少后续视觉调整成本，后者防止已经对齐的页面在迭代中悄悄退化。
