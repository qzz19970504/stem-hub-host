# stem-hub Host 深色控制台重建设计

## 目标

以 `docs/design_dark.png` 为唯一视觉基准，在保留现有 PySide6、串口线程、Controller、AT 协议和三个 Tab 的前提下，重建一个固定 `1600x900` 的深色工业控制台。第一页需要达到接近像素级的布局、字体、配色、状态和动效一致性，同时保持真实硬件操作语义。

## 范围

- 首轮完整重建 Console 页，并把设计令牌和字体基础设施应用到 Charts 与 Passthrough 页。
- 不修改固件协议，不增加固件不存在的伪命令。
- 保留现有串口握手、定时采样、绘图、透传与 AT 终端能力。
- 默认窗口固定为 `1600x900`；允许 F11 和双击顶部空白区切换全屏。
- 全屏保持固定构图与卡片相对高度，不进行自由流式重排。

## 视觉架构

### 根窗口

- 客户区基准尺寸为 `1600x900`。
- 深黑蓝外层背景内放置一圈细青色边框和克制的内侧辉光，复刻目标图的设备面板轮廓。
- 采用单一视觉令牌模块管理颜色、间距、圆角、字号、动画时长、描边和阴影。
- 所有页面共享同一背景、Tab、控件状态和字体体系。

### Console 页布局

页面由 Tab 栏、串口栏和两行三列主栅格组成。

- 三列宽度比：`1 : 1.26 : 1`。
- 顶行：电池、驱动、输出控制。
- 底行：2x2 温度区、跨中右两列的 AT 终端。
- 顶行和底行使用固定设计高度；窗口全屏时保持相对比例并将多余空间分配给外层留白。
- 卡片边框、圆角和间距按目标图统一，不嵌套装饰性卡片。

### 串口栏

- 左侧依次为端口下拉框、连接状态、连接动作。
- 端口下拉框展开前自动刷新端口，去掉占位过大的文字 Refresh 按钮。
- 未连接时动作按钮为绿色并显示 `CONNECT`。
- 已连接或握手中时动作按钮为红色并显示 `DISCONNECT`。
- 状态标签独立显示 `OFFLINE`、`OPENING`、`CONNECTED` 或错误摘要。
- 所有连接相关控件具有 hover、pressed、focus 和 disabled 状态。

### 电量卡

- 中央显示电池图标和一位小数电压。
- 电量环由背景轨道、主进度弧、端点辉光和低强度呼吸光组成。
- 电压变化触发 450ms 缓动插值；不持续旋转整条进度弧，避免状态含义漂移。
- 颜色按正常、警告、危险三级变化。
- 电量范围集中配置，默认 `28.0V` 为 0%、`37.0V` 为 100%；固件以后给出明确阈值时只修改配置值。
- 无数据时显示 `--.-V`，停止高亮动画并使用低对比度轨道。

### 驱动卡

- MODE 区放大为卡片视觉焦点，模式文本与当前动作颜色联动。
- CURRENT 区只显示固件返回的电流，不保留没有实际行为的调节符号。
- SLEEP、WAKE、FWD、REV、BRAKE、STOP 六个按钮等宽排列。
- 每个按钮使用自绘矢量图标；选中、悬停、按下、键盘焦点和禁用状态完整。
- 握手前全部禁用；命令错误时恢复上一个已确认状态并写入 AT 日志。

### 输出控制卡

- 五个真实开关：`CHARGE`、`DISCHARGE`、`NMOS 1`、`NMOS 2`、`LIGHTS`。
- `CHARGE` 直接映射 `LM51770`，`DISCHARGE` 直接映射 `MP4317`。
- 充电和放电互斥，切换时先关闭另一通道，再打开目标通道。
- 第六个位置为红色 `ALL OFF` 安全动作，依次关闭 LM51770、MP4317、NMOS1、NMOS2 和 LED；它不是虚假 toggle。
- 删除没有固件 API 的 `BALANCING` 状态。
- 故障区只显示可证明的状态：OVERTEMP、OVERCURRENT、UNDERVOLTAGE、DRV FAULT、AUX FAULT。
- OVERTEMP 由任一有效温度达到配置阈值推导；OVERCURRENT 来自 MotorState；UNDERVOLTAGE 来自电池配置阈值；DRV/AUX 来自 `AT+FAULT?`。

### 温度和 AT 终端

- 温度区保持 2x2，小卡内容改为无多余内层边框的紧凑信息块。
- 温度计图标、数值和标签严格对齐，颜色只承载温度告警语义。
- AT 终端沿用真实日志与输入能力，去除时间戳造成的视觉噪声，使用 TX/RX/INFO/ERR 颜色区分。
- 输入区固定在底部，发送按钮与目标图尺寸一致；滚动日志不改变整体卡片高度。

## 字体与图标

- 将开源字体作为应用资源随源码和 PyInstaller 包分发，不依赖目标机器字体安装状态。
- 英文标题和标签使用窄体显示字体，数值与终端使用等宽字体，中文错误信息使用内置中文字体回退。
- 应用启动时先用 `QFontDatabase.addApplicationFont` 注册字体，再创建任何窗口或控件。
- 字体加载失败时记录明确警告，并回退到 Segoe UI、Microsoft YaHei UI 和 Consolas。
- 图标使用 QPainter 矢量绘制，避免外部 SVG 缩放和打包路径问题。

## 数据流与错误处理

- UI 信号继续进入 Controller，由 Controller 生成 AT 命令并交给 SerialWorker。
- Controller 返回的已确认状态是 UI 的唯一权威来源；本地点击只提供短暂 pending 反馈。
- 握手未完成时，电机、输出、终端发送和透传控制保持禁用。
- 断开串口时清空动态数值、关闭本地 toggle 状态、停止高亮动画，并保留日志供诊断。
- 串口错误和协议错误同时进入状态标签与 AT 日志，不能静默失败。
- UI 更新保持现有 100ms 刷新节奏；电量和 toggle 动画独立运行，不阻塞串口线程。

## 全屏行为

- 普通模式固定 `1600x900`，不允许任意缩放。
- F11 或双击 Tab 栏空白区域进入或退出全屏。
- Escape 只在全屏状态下退出。
- 全屏时中央内容保持设计宽高比；额外空间由外层背景吸收，卡片不会被无限拉高。

## 测试与视觉验收

- 为电压、温度和电流解析及电量比例增加单元测试。
- 为输出开关到 Controller 命令的映射、互斥行为和 ALL OFF 顺序增加测试。
- 为串口连接按钮的绿色/红色状态、握手门禁和全屏切换增加 Qt 测试。
- 使用 fake firmware 在 `1600x900` 截取已连接和未连接两张 Console 图。
- 用像素对比和人工审查检查：字体非方块、卡片比例、文字不溢出、按钮位置、颜色、辉光、五种控件状态和电量动画中间帧。
- Charts 与 Passthrough 至少进行全屏和 `1600x900` 截图检查，确保没有重叠或裁切。

## 完成标准

- Console 页的宏观构图、层级、三列比例、按钮位置、字体气质和颜色关系与目标图基本一致或更精炼。
- 未安装任何额外字体的机器和 PyInstaller 可执行文件中仍能正确显示英文、数字和中文。
- 未连接按钮为绿色，已连接按钮为红色。
- 电量环随电压平滑变化，且状态颜色正确。
- 充电、放电、NMOS1、NMOS2、灯、ALL OFF、电机、AT、图表、透传功能均可通过 fake firmware 或现有测试证明没有退化。
- 普通窗口固定，且全屏进出可靠，无卡片高度漂移。
