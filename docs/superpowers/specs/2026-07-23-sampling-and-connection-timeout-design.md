# 整数采样频率与有限连接握手设计

日期：2026-07-23  
状态：已确认，待实施  
适用项目：`D:\Codes\STM32\stem-hub-host`

## 1. 目标

本轮修改解决三个具体问题：

1. 采样频率控件不再允许小数，范围为 1–20 Hz，默认 1 Hz。
2. 绘图横轴使用与采样一致的真实秒时基。
3. 串口连接和固件握手不再无限重试；连接失败后自动恢复为可重新选择
   端口的未连接状态，并只提示一次最终失败。

同时保留 `--fake` 无硬件联调入口，让没有下位机时也能检查完整 UI 和
控制流程。

## 2. 采样频率

### 2.1 UI 契约

- `QDoubleSpinBox` 改为 `QSpinBox`。
- 最小值：1 Hz。
- 最大值：20 Hz。
- 步进：1 Hz。
- 默认值：1 Hz。
- 显示格式保持 `<整数> Hz`，不显示小数位。

### 2.2 Controller 契约

- Controller 的采样频率使用整数语义。
- 公开设置接口把输入归一化为整数，并只接受 1–20 Hz。
- 轮询定时器间隔为 `round(1000 / Hz)` 毫秒。
- 默认轮询间隔为 1000 ms。
- 修改频率后，活动中的定时器立即使用新间隔。

一次轮询仍按现有协议发送 SENSE、FAULT、MOTOR 三条查询；本轮不改变
固件协议和命令集合。

## 3. 绘图时基

`DataBuffer` 已使用 `time.monotonic()` 记录真实采样时间，本轮保留这一
正确模型，并增加明确的绘图时基契约：

- 横轴单位为秒。
- 最新样本显示为 0 秒，历史样本显示为负的真实经过秒数。
- 采样率为 `N Hz` 时，相邻理想采样点间距为 `1/N` 秒。
- 改变采样率不会重写既有数据时间戳，也不会假设所有点等距。
- 数据保留窗口继续为最近 300 秒。
- 图表显示范围固定为最近 300 秒到当前时刻，即 `[-300, 0]` 秒，
  从而在不同采样率下保持相同的时间尺度。

## 4. 串口连接状态机

### 4.1 状态

- `OFFLINE`：未连接，端口可选择，按钮为绿色 `CONNECT`。
- `CONNECTING`：串口已打开、正在握手，端口不可选择，按钮为
  `DISCONNECT`。
- `CONNECTED`：握手成功，按钮为红色 `DISCONNECT`。

`ERROR` 不再作为一个需要用户手动断开的持久状态。失败原因写入日志并
通过一次对话框显示，随后 UI 保持 `OFFLINE`。

### 4.2 时间与重试

- 串口打开成功后延迟 200 ms 发起第一次握手。
- 单次握手等待上限为 500 ms。
- 失败后约 1 秒再次尝试。
- 从串口打开开始计算，总连接期限为 5 秒。
- 期限内收到有效 `+VERSION` 和 `OK` 即成功，立即取消所有握手定时器。
- 达到期限后不得再发送握手命令。

总期限优先于固定重试次数，因此即使事件循环存在轻微调度抖动，用户
感知到的连接等待时间仍稳定在约 5 秒。

### 4.3 失败和取消

串口本身无法打开：

1. 不进入后台重试。
2. UI 保持或恢复 `OFFLINE`。
3. 日志记录底层打开错误。
4. 弹出一次“连接失败”对话框。

串口已打开但握手在 5 秒内未成功：

1. 停止握手延迟、重试和连接期限定时器。
2. 主动关闭 worker。
3. 清空连接期状态和旧遥测缓存。
4. 通过现有 `disconnected` 数据流恢复端口选择、绿色 `CONNECT` 和
   所有控制门禁。
5. 日志记录最终原因。
6. 弹出一次“连接失败”对话框。

用户在 `CONNECTING` 期间点击 `DISCONNECT`：

- 立即取消连接与全部定时器并关闭串口。
- 恢复 `OFFLINE`。
- 这是用户主动取消，不弹失败对话框。

来自旧端口或旧连接轮次的延迟定时器不得影响新连接。

## 5. UI 提示

`MainWindow` 负责最终用户提示，Controller 只报告结构化的连接失败
信号和原因。这样连接状态机可独立测试，并避免 Controller 依赖
`QMessageBox`。

失败对话框：

- 标题：`连接失败`
- 正文：说明端口未能在 5 秒内完成握手，或显示串口打开失败原因。
- 每轮连接最多出现一次。

对话框出现前，串口和 UI 状态必须已经恢复为 `OFFLINE`，避免用户关闭
对话框后仍看到 `ERROR / DISCONNECT`。

## 6. 无硬件联调

以下两个入口均使用内置 `FakeFirmware`：

```powershell
& 'env\release\Scripts\python.exe' -m stem_hub_host.main --fake
& 'dist\stem-hub-host.exe' --fake
```

fake 模式自动创建并打开 `FAKE0`，模拟版本握手、遥测与控制命令。它是
人工检查可操作界面的推荐入口。

`pytest` 用于自动回归，不作为持续展示界面的程序。文档将明确：

- 指定测试文件：`python -m pytest tests/test_connection_flow.py -q`
- 全量测试：`python -m pytest tests -q`
- 可视化人工联调：使用 `--fake`

## 7. 测试策略

实施严格按测试先行：

### 7.1 采样和绘图

- 控件是 `QSpinBox`，范围 1–20，默认 1，步进 1。
- Controller 默认频率为 1，定时器间隔为 1000 ms。
- 1、2、3、20 Hz 映射到预期整数毫秒间隔。
- 非法输入不改变当前频率。
- 图表横轴范围为 `[-300, 0]` 秒。
- 已有数据使用真实时间戳归一化，不因采样率改变而重写。

### 7.2 连接

- 无响应时在有限期限后关闭 worker，不再有活动重试定时器。
- 最终失败只发出一次。
- 失败信号发出时 worker 已关闭。
- 握手成功会取消期限和重试定时器并开始轮询。
- 用户主动关闭不会报告连接失败。
- 串口打开失败立即回到 `OFFLINE` 并提示一次。
- 旧连接的延迟回调不会污染快速重连。

为缩短自动测试时间，Controller 的连接期限和重试间隔通过构造参数
注入，生产默认值仍固定为 5 秒和 1 秒；测试使用更短的等价时序。

### 7.3 完整验证

- 全量 `pytest`

- 16 张 Dark/Light 黄金截图视觉回归
- `--fake` 源码启动验证
