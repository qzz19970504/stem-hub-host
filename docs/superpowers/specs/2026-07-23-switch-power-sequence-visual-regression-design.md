# Switch、功率通路时序与视觉回归设计

日期：2026-07-23  
状态：已确认，待实施  
适用项目：`D:\Codes\STM32\stem-hub-host`

## 1. 目标

本轮改动同时解决三个问题：

1. 将右上角输出 Switch 调整为成熟、紧凑且符合现有仪表盘尺度的比例。
2. 将充电与放电功率通路切换改为逐条等待设备确认的三段式安全时序。
3. 落实视觉优化路线的第一阶段和第五阶段：建立统一设计令牌，并建立可重复执行的黄金截图视觉回归。

窗口结构、第一页 2×3 布局、串口协议格式、五个真实输出、日夜主题、固定窗口与 F11 全屏行为保持不变。

## 2. Switch 设计

### 2.1 几何

选择“仪表盘均衡版”：

- 控件宽度：60 px
- 控件高度：36 px
- 有效轨道宽度：60 px
- 有效轨道高度：36 px
- 拨片直径：28 px
- 拨片与轨道端部间距：4 px
- 轨道宽高比：1.667
- 拨片填充：100% 不透明纯白

该比例沿用 Material 3 `52×32`、选中拨片 `24 px` 的几何关系，并按当前 1600×900 工业仪表界面的视觉重量放大一档。

### 2.2 状态

Switch 必须支持：

- 默认：暗色或浅色主题的未选中轨道，实心白色拨片。
- 选中：主题 Accent 实色轨道，实心白色拨片。
- 悬停：只增强边框或状态层，不改变几何。
- 按下：拨片轻微压暗，不改变直径和轨道尺寸。
- 聚焦：显示清晰的键盘焦点描边。
- 禁用：降低轨道和拨片对比度，仍能辨认当前状态。
- 动画：拨片使用现有短时缓动从一端移动到另一端。

颜色、尺寸、描边、阴影透明度和动画时长全部来自 `theme.py`，控件实现中不保留视觉魔法数字。

## 3. 功率通路语义

### 3.1 专业命名

- `CHARGE`：充电模式 / Charge Path，由 LM51770 控制。
- `DISCHARGE`：放电模式 / Discharge Path，由 MP4317 控制。
- `OFF`：功率通路关闭状态。

UI 继续显示 `CHARGE` 和 `DISCHARGE`，避免协议、测试和用户操作习惯发生无关变化。

### 3.2 进入充电模式

控制器严格按下列顺序发送命令，每一步必须收到 `OK` 后才允许执行下一步：

```text
AT+MP4317=OFF
AT+LM51770=OFF
AT+LM51770=ON
```

含义：

1. 先关闭放电通路，保证互斥。
2. 再显式关闭一次目标充电器件，使目标通路从确定的 OFF 状态启动。
3. 最后开启 LM51770。

### 3.3 进入放电模式

控制器严格按下列顺序发送命令，每一步必须收到 `OK` 后才允许执行下一步：

```text
AT+LM51770=OFF
AT+MP4317=OFF
AT+MP4317=ON
```

含义：

1. 先关闭充电通路，保证互斥。
2. 再显式关闭一次目标放电器件，使目标通路从确定的 OFF 状态启动。
3. 最后开启 MP4317。

### 3.4 进入 OFF 状态

保持现有安全关闭顺序：

```text
AT+LM51770=OFF
AT+MP4317=OFF
```

关闭命令即使其中一步失败，也继续尝试关闭另一通路；OFF 操作不得因为首个器件返回错误而跳过第二个关闭命令。

### 3.5 排队与失败行为

- 同一时间只允许一个功率通路状态机运行。
- 快速连续请求保留最后一个目标模式，并在当前转换完成后串行执行。
- 任一“进入模式”的 OFF 步骤失败时，立即终止后续 ON 命令。
- 最终 ON 命令失败时结束转换并保持 UI 为未开启状态。
- `output_command_failed` 必须标识实际失败的控件和目标状态。
- 转换期间禁用 CHARGE、DISCHARGE 与 ALL OFF 之外可能造成冲突的操作；现有排队规则保持有效。
- 断线时清空转换状态和排队目标。

## 4. 第一阶段：统一设计令牌

### 4.1 单一来源

`stem_hub_host/ui/theme.py` 作为视觉参数的单一来源，新增并组织以下令牌：

- Switch 几何与绘制：宽、高、拨片直径、间距、描边宽度、阴影偏移与透明度。
- 通用控件：小型/标准控件高度、边框宽度、焦点边框宽度。
- 圆角：小、中、大、胶囊。
- 间距：现有 4 px 基准体系及常用布局组合。
- 动效：快速、标准、遥测动画时长和统一 easing 语义。
- 表面效果：禁用透明度、弱/强辉光透明度、卡片阴影参数。

### 4.2 QSS 令牌化

`style.qss` 不再直接承担主题颜色定义。颜色以具名占位符表示，由 `stylesheet.py` 使用当前 `theme.py` 调色板渲染。

要求：

- 所有占位符必须可解析。
- 渲染后的 QSS 不得残留占位符。
- 日夜主题使用同一份结构 QSS。
- 状态专用颜色必须使用语义名称，例如 Accent、Success、Warning、Danger、Disabled，而不是器件名称。

### 4.3 迁移边界

本轮迁移当前界面共享的颜色、圆角、控件高度、间距、描边、阴影、辉光和动画参数。绘制算法内部用于路径构造的局部比例可以保留，但必须以有意义的类常量表达，不散落匿名数字。

不在本轮重写所有控件，也不改变现有页面信息架构。

## 5. 第五阶段：视觉回归

### 5.1 确定性截图

视觉审计工具固定以下输入：

- 捆绑字体已注册。
- 固定颜色主题。
- 固定窗口尺寸和全屏审计尺寸。
- 固定 fake 遥测、故障、输出和日志内容。
- 动画在截图前直接设置为终态。
- 截图输出记录主题、页面、状态和逻辑尺寸。

覆盖矩阵：

- 主题：Dark、Light。
- 页面：Console、Charts、Passthrough。
- 视图：1600×900 固定窗口、明确尺寸的全屏审计视图。
- Console 状态：Connected、Disconnected。

### 5.2 黄金基线

黄金图片保存在版本控制内的专用目录，与临时截图分离。基线只能通过显式更新命令生成，普通测试不得静默覆盖。

每张基线同时记录：

- 文件名和 SHA-256。
- 像素尺寸。
- 主题、页面和状态。
- 生成工具版本字段。

### 5.3 比较指标

比较工具输出：

- 尺寸是否完全一致。
- 平均 RGB 绝对差。
- 超过单像素容差的像素占比。
- 最大通道差。

默认验收阈值：

- 尺寸必须一致。
- 平均 RGB 绝对差不高于 `3/255`。
- 通道差大于 12 的像素占比不高于 1%。

字体抗锯齿存在平台差异，因此黄金比较定位为同一 Windows 构建环境的严格检查；跨机器仍以几何契约测试和人工截图审查为准。

### 5.4 自动化层级

1. 普通 `pytest`：运行快速视觉契约测试，不启动整套截图生成。
2. 视觉审计命令：生成完整矩阵并与黄金基线比较。
3. 发布前：行为测试、视觉审计、PyInstaller 构建和 EXE 启动验证全部通过。
